# BFStaff r40.6: мобильная доводка редактора аттестации

Основание: ветка `r40.6-attestation-editor`, SHA `aa4014042bcfe23e18b9e76bfe46678fab00c8de`.

## Что изменено

- **Настройки:** строки раздела, числа «Взять» и корзины используют одну мобильную сетку и элементы одинаковой высоты (44 px). Ширины ограничены контейнером; справа ничего не должно выступать за карточку.
- **Банк вопросов:** два нативных селектора «Категория» и «Статус» размещены рядом, **в одной строке** на любых мобильных ширинах. На iOS/Android используется системный выбор; фильтрация по прежней логике.
- Счётчики «Активных / Архив / Показано» сокращены по высоте и внутренним отступам.
- Три кнопки «Результаты / Вопросы / Настройки» унифицированы по размеру и центрированию текста.
- Добавлены 4 точечных структурных regression-теста в текущий файл тестов.

## Установка с телефона

Загрузить **четыре исходных файла** из архива, сохраняя путь `src/...` и `tests/...`, в **ветку `r40.6-attestation-editor`**. Файл в `docs/` необязателен для работы приложения.

**Не загружать в `main`.** Никаких миграций, auth-контрактов или Edge Functions нет. Отдельных GitHub Actions также не добавлено (они отложены).

## Проверки перед передачей

- Сверены blob SHA исходных файлов с актуальным head GitHub.
- Синтаксис TSX трёх компонентов: PASS (TypeScript transpilation).
- Четыре новые структурные проверки Node: PASS.
- Полная сборка из GitHub и интерактивная проверка PWA **не выполнены** на этом этапе. После загрузки нужны Vercel status и проверка на телефоне.

## Ручная проверка на телефоне

1. Банк вопросов → вкладка «Вопросы»: справа от селектора категории должен находиться селектор статуса, они всегда на одном уровне.
2. Выбрать категорию «Бар», статус «Архив»: видны только архивные вопросы Бара.
3. Проверить размер трёх счётчиков, выравнивание названия «Результаты» в табах.
4. Настройки → категория Бар → строки разделов: ячейки и корзины стоят на одном горизонтальном уровне, скролл страницы только вертикальный, правый край не выступает.
5. Изменение числа вопросов без сохранения и проверка сохранения остаются по прежней логике.
