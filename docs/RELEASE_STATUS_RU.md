## Что можно установить

Для новой ветки загрузить содержимое app/ в корень репозитория; либо хранить весь пакет и выбрать Root Directory = app в Vercel. Node24, npm ci, npm run typecheck, npm run build. Настройки Supabase/Worker и same-origin rewrites vercel.json основаны на main. Ветка не создаёт отдельную базу: при одинаковом окружении данные общие с production. ZIP содержит исходники и dist, node_modules не включены. Локальный ПК для работы опубликованного сайта не нужен.

Ничего не отправлено в GitHub и не опубликовано. Для безопасного отдельного preview перед включением записей нужны ваши отдельное разрешение и настройки окружения; реальные production-записи в этой работе не выполнялись. Не использовать E2E-моки как production backend.

## Реальный незакрытый блокер

В checkout нет проверенного способа физического удаления управляемых вложений NocoDB. Для него описан, но ещё не реализован/не проверен реальный private cleanup adapter. Поэтому новый Worker намеренно не рекламирует lifecycle/photoCleanup без рабочего адаптера; удаление/архивирование с каскадом и замена/удаление фото рецептов могут быть недоступны. Это не «полностью готовый production релиз». Обычные чтение/создание/редактирование без таких операций сохраняют main API. Нельзя включать capability вручную для обхода проверки.
