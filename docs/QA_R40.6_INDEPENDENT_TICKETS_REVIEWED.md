## Оставшиеся непроверенные сценарии и риски

1. Реальный изолированный Supabase: полный набор миграций, PostgREST, RLS, реальные JWT, Auth/Edge Functions и несколько соединений. Использована минимальная синтетическая auth/profiles-схема и шесть фактических миграций аттестации; версия PostgreSQL PGlite может отличаться от целевой.
2. Параллельные SQL-транзакции двух администраторов/двух устройств, время ожидания и производительность отложенных row-trigger на реальном объёме. Общий порядок блокировок и идемпотентность подготовлены; многосессионный результат не заявляется.
3. Реальные 334 production-вопроса и исторические попытки в этой сессии не читались и не сверялись. До установки нужны резервная копия, read-only preflight, проверка типов, групп, планов, количества, ID и истории; затем такая же сверка после установки на тестовой копии.
4. Сервер сохраняет старый aggregate-only контракт: клиент сообщает correct/total и офлайн-порог. Проверка диапазонов/ID/ревизий не доказывает правильность ответов. Для доверенного оценивания нужен отдельный серверный протокол со снимком билета и ответами. Это существенное ограничение production-подтверждения.
5. Safari/iOS, Android WebView, экранная клавиатура, safe-area, приватный режим, физическое исчерпание квоты и Web Locks без поддержки. Проверены Chromium и программные отказы хранилищ; это не реальные устройства.
6. Установленная PWA: обновление service worker, первый холодный запуск без сети, скачивание нового lazy chunk, долго открытая старая вкладка. Проверка IndexedDB выполнена с serviceWorkers blocked; проверка сборки не подтверждает эти сценарии.
7. При потерянном ответе сервера возможен повтор запроса с тем же client_attempt_id. Это необходимо для восстановления; сервер должен хранить одну попытку. «Никогда не повторяется сетевой запрос» не заявляется.
8. Непроходимые активные планы останавливают миграцию; неизвестные старые категории остаются черновиками. Legacy-клиенту доступны только BF-билеты без точной квоты, которые он способен собрать из собственных исходных вопросов. Нельзя обещать полноценный rollback старого фронтенда для новых независимых билетов.
9. Два исходных workflow-теста и общий browser-suite остаются непройденными. Их следует решать отдельно в разрешённом объёме перед общим релизом.

Production Supabase, main, GitHub Actions, авторизация и права Owner/Admin не изменялись. Commit, push, PR и deploy не выполнялись.
