# Дальнейшая установка проверенного пакета

Использовать исправленную рабочую копию/архив REVIEWED, а не исходный CANDIDATE и не его прежний APPLY_TO_CHECKOUT.py. Отчёты CANDIDATE отражают состояние до исправлений.

1. Сохранить текущую сборку и обеспечить восстанавливаемую копию БД. Для локальной проверки БД backup production не нужен: использовать PGlite или отдельный безопасный тестовый Supabase. Production пока не изменять.
2. Сверить ветку `r40.6-attestation-editor`, `git rev-parse HEAD`, `git status --porcelain` и изменения после `2a21ea6a486c2aeaba144bcb6325583ccb370b85`. Сейчас HEAD совпадает. На новом SHA сначала повторить совместимость; на грязное дерево автоматически не накладывать.
3. Рабочая копия уже исправлена: повторно применять installer нельзя. Для нового чистого checkout этого SHA применить `APPLY_REVIEWED.py` из архива REVIEWED либо reviewable patch. Скрипт проверяет HEAD, ветку, чистоту, исходные и целевые хеши, затем записывает только локальные файлы; SQL не исполняет. Инструкции/manifest внутри REVIEWED имеют приоритет перед CANDIDATE.
4. Node 24.x: `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, `node --test tests/attestation-independent-tickets-v3.test.cjs`, `node --test tests/attestation-offline-sync-v3.test.cjs`, `npm run test:attestation:sql`, `npm run test:attestation:browser`. Никакой production env этим локальным тестам не требуется. Новые browser-тесты сами запускают Vite с фиктивным localhost API и блокируют внешние запросы.
5. Полный `npm test` пока имеет два исходных workflow-сбоя; общий `npm run test:browser` — исходный download-сбой в редакторе знаний. Не обходить их выключением тестов; решить отдельно в разрешённом объёме. Сейчас это препятствует общему release-gate, хотя scoped проверки аттестации проходят.
6. В отдельном разрешённом тестовом Supabase той же версии выполнить read-only preflight: фактические схема/роль/grants, все IDs/статусы/группы/типы вопросов, планы, активные категории, суммы квот, пустое «Бистро», quiz_attempts и question_versions. Сохранить до/после выборки и snapshot/backup. Не использовать production credentials в этом окружении.
7. После проверки окружения применить **одну новую исправленную миграцию** `20261012120000_attestation_independent_tickets_v3.sql` обычным runner в одной транзакции. Не повторять seed/старые миграции, не использовать reset/очистку. При ошибке исправить и повторить на тестовой базе, не пытаться принудительно завершить production-миграцию.
8. На тестовом сервере проверить RPC v3 и legacy, staff/Owner/Admin, BF/BB/common, независимость двух билетов одного типа, перенос/архив общего вопроса, неверные планы/квоты, конкуренцию администраторов, старую ревизию в офлайн-очереди, историю/результаты и идемпотентность при потерянном ответе. Полностью сверить ID/количество/статусы и старые результаты.
9. После готовности серверных RPC проверить клиент в отдельном preview **только при разрешении на этот шаг**. SQL/RPC должны предшествовать новому клиенту. Проверить физические устройства 320/375/390/430, установленную PWA, обновление SW, офлайн-холодный запуск, v2/v3 кеш, приватный режим, смену аккаунта и переполнение хранилища. Старые вкладки редактора закрыть перед переходом.
10. Production — только после отдельного явного разрешения, полного release-gate, резервной копии и конкретного review изменений. В этой сессии commit/push/PR/deploy/production SQL запрещены и не выполнены.

Откат: старый фронтенд работает только с совместимыми BF-билетами, доступными legacy-адаптеру. Не удалять новые SQL-поля/вопросы/билеты/историю и не очищать IndexedDB/outbox. Новые независимые билеты требуют v3; полноценный откат БД с новыми данными — отдельная миграция и разрешение.

11. Поправка v4 устраняет `CategoryMotionIcon` с экрана выбора. После установки повторить npm run typecheck, npm test, npm run build и test:attestation:browser на полной рабочей копии. До этого не считать релиз готовым.
