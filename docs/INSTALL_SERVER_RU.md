# Серверный перенос: отдельное разрешение

Этот пакет содержит обычный рабочий React/Vite frontend, а не демо-Context. Main HEAD и бизнес-API сохранены. ZIP не запускает SQL, Edge deploy или Worker deploy автоматически.

1. Для отдельного preview сохранить main как есть. Распаковать пакет; исходное приложение в app/. Если содержимое app/ загружается в корень новой ветки, новые документы/patches также сохранить рядом для оператора. Если загружается весь пакет, в Vercel выбрать Root Directory app. Связать проверенные env и rewrites. При одинаковых Supabase/NocoDB окружениях базы будут общими с main; отдельная ветка не копирует данные.
2. Без серверных патчей обычные существующие main API работают, но новые операции честно закрываются или получают серверный отказ. Обратный порядок имени требует нового staff-login; открытие/закрытие неполной смены требует R22 SQL; личная история — отдельного scoped READ RPC; underline/cascade/delete/media — ordered lifecycle patches.
3. Перед реальным применением проверить backup и действия SQL на тестовом окружении. Изменения только после отдельного разрешения владельца. docs/patches/material-lifecycle-README.md — точный порядок и rollback. Не добавлять service_role в VITE_* или клиентский bundle.
4. Физическая очистка NocoDB пока НЕ реализована в реальном storage adapter. Не включать capability вручную. Нужны подтверждённые версия/тип хранилища NocoDB и поддерживаемый способ удаления managed attachments; внешний URL не даёт права удалять чужой файл. До реализации adapter замена/удаление фото и связанные recipe lifecycle операции остаются fail-closed.
5. Затем на отдельном preview проверить настоящий вход/восстановление/роли и сохранение каждого раздела с разрешённым тестовым аккаунтом. Browser transport fixtures и PGlite не заменяют production RLS/Storage/NocoDB/Cloudflare verification. Проверить установленную PWA и реальные push на телефоне.

GitHub/ветки/commits/push/PR и production в этой работе не менялись. Начальное разрешение GitHub read-only по-прежнему действует.
