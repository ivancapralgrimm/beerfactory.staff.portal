# Вход, регистрация и восстановление — выбранный концепт

Изменена только презентация существующих auth-экранов: общая оболочка AuthLayout, видимые подписи полей, медная объёмная кнопка, подчёркнутые ссылки, локальная иллюстрация из второго пользовательского изображения и бумажный фон. Вход сохраняет одно поле имени/фамилии и пароль 4–12 цифр; регистрация и восстановление сохраняют исходные поля, проверки, обработчики API и состояния ошибки/ожидания. Setup recovery также использует общую оболочку.

Предоставленная иллюстрация не перерисована. Нейтральная бумажная текстура сгенерирована отдельно для устранения видимых стыков первоначального маленького фрагмента. Поверхность кнопки взята из пустой области выбранного концепта, подпись остаётся HTML. Geist900 сохранён локально; OFL-лицензия в licenses и public/third-party-notices.txt. Веб-сайт не обращается к внешнему API генерации или шрифтов.

Всё оформление ограничено классом bf-auth-scene и новым CSS-модулем. Основной портал, аватары, роли, данные, серверные функции и схемы не менялись. Motion мягкий, системное reduced-motion учитывается. Если иллюстрация недоступна, форма остаётся рабочей. Ассеты включены в precache PWA.

Контроль: production build + TypeScript, CI113/113, 19/19 целевых browser/layout/keyboard/precache сценариев, 21/21 общий browser regression. Все API/WS в браузерных проверках синтетические; реальная production-авторизация/запись и физический iPhone не проверялись. Прежние ограничения серверных патчей RC1 остаются.

Снимки и попарные сравнения: qa/r407/evidence/auth-concept. Визуальный отчёт: design-qa.md. PDF: docs/AUTH_CONCEPT_SCREENS.pdf. Классификация расхождений/исправлений и измеренные области приведены в отчёте; это реализация концепта, не заявление пиксельной идентичности растра.
