# r40.6 Attestation UI cleanup + per-category ticket sizes

Base: r40.6-attestation-editor @ 87126156e257fb88faa14ef6eaa9b682646475c6

Changes:
- Question IDs and revisions are no longer rendered to editors.
- Internal question group/source/sourceRef fields remain in data but are hidden from the normal editor UI.
- "Тема" is presented as "Раздел вопросов". Sections drive balanced ticket composition and weak-area reporting.
- Global questions-per-test control is removed from the editor.
- Each category now has its own questionsPerTest (1..50).
- Numeric controls use string drafts + inputMode=numeric, so fields can be temporarily empty without a leading zero.
- Category technical ordering is hidden from the normal UI.
- Category enable/disable is under "Дополнительно".
- Audit journal is condensed into two human-facing blocks and does not render raw action/entity codes or internal IDs.
- Mobile editor controls are forced to >=16px inside AppShell to prevent iOS focus auto-zoom without disabling user pinch zoom.

Backend:
- Migration 20261007082211_attestation_category_ticket_sizes is already applied to live Supabase.
- Do not run it manually.
- save_attestation_editor_settings_v2 validates per-category totals and topic capacity.
- Old save_attestation_editor_settings is no longer executable by authenticated clients.

Recipes:
- Current RecipeEditor/RecipeDetail/RecipesPage were audited: recordId/internal recipe IDs are used for routing/API calls but are not rendered as editor-facing text. No recipe data contract change is needed for this cleanup.
## Mistake review navigation

- Recipe mistakes now open the exact recipe detail page using the preserved source-aware recipe ID.
- Knowledge mistakes open the exact Knowledge article page.
- The old `/menu?q=...` recipe-search fallback is removed.
- If an old question has no resolvable direct material route, no misleading search button is rendered.
