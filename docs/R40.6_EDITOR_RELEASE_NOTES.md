# BFStaff r40.6 — full attestation editor

Base branch required:
- `main` at `e7b19d443eb4273afed394d86d23aba62a403f63` or newer with the repaired auth flow.

## Included

- Online attestation bank with create/edit/archive/restore/delete for questions.
- Pass threshold editor (50–100%).
- Questions-per-ticket editor (1–50).
- Ticket-plan editor per category and topic.
- Category create/rename/order/disable/restore.
- New categories are created disabled so they cannot appear in staff attestation before they are ready.
- Category activation is rejected unless its saved ticket plan totals the global ticket size and every topic has enough active question groups.
- Questions can be prepared inside disabled categories before publication.
- Optimistic concurrency for questions, settings and categories.
- IndexedDB bank cache + offline attempt outbox.
- Authenticated-only sync bridge mounted inside `AppShell`.

## Security model

Attestation tables stay RLS-enabled with direct table access withheld. The editor uses authenticated `SECURITY DEFINER` RPCs which all enforce `private.attestation_is_admin()` internally. `PUBLIC` and `anon` do not receive execute access to the new mutation RPCs.

Supabase Advisor reports the existing RPC-only RLS / `SECURITY DEFINER` informational warnings. Those are expected for this architecture; non-admin RPC access was separately tested and rejected.
