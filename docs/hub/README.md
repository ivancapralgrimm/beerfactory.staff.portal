# Hub и Factory Run

В «Разделы» добавлен Hub (`/#/hub`). Первая карточка открывает отдельный защищённый маршрут `/#/hub/factory-run`. Доступ использует существующую авторизацию портала. Чтобы добавить следующий проект, добавьте его карточку в `HubPage` и отдельный маршрут; текущая игра изолирована в `src/features/hub`.

Factory Run — оригинальный трёхполосный раннер по пивоварне: кружка-маскот, хмель, бочки, трубы и ящики. Каждые 10 шишек дают бонус за партию. Скорость постепенно растёт, на рейс есть три попытки. Содержимое и графика не являются копией Subway Surfers.

## Управление

- Свайп влево/вправо меняет дорожку.
- Свайп вверх или короткое касание запускает прыжок.
- Свайп вниз включает подкат и приземляет после прыжка.
- На компьютере работают стрелки/WASD, пробел и Escape.
- Экранных кнопок движения нет. Для запуска, паузы и повтора остаются обычные доступные кнопки.

Открытие «Разделов», уход фокуса из игры, потеря фокуса окна и скрытие вкладки ставят рейс на паузу. Возобновление явное. Пауза при уходе в общую навигацию сохраняет там фокус. Во время паузы и на неподвижной карточке Hub игровой RAF не работает.

## Графика и данные

Основная сцена — настоящий WebGL/Three.js 0.187, процедурные 3D-модели, PBR-медь, стекло, освещение и тени. Это стилизованная игровая графика, не заявленный фотореализм. Unity runtime не подключался. Модели не скачиваются с внешнего API/CDN; логотип берётся из существующего фирменного ассета.

Доработка графики: `runner-materials.ts` создаёт оригинальные карты цвета, высоты и шероховатости для досок с волокнами/сучками, кирпича, меди, пива и пены. На ёмкостях есть шкалы приборов, люки, фланцы и вентили; добавлены подвесные светильники. У кружки рельеф стекла, объёмная ручка, жилет с нашивками, воротник, галстук, перчатки и обувь. Подкат меняет позу, сохраняя пропорции кружки. Это процедурные игровые материалы, не фотографические сканы.

CPU-карты переиспользуются в пределах одного набора цветов, а GPU-текстуры принадлежат конкретному рендереру и освобождаются при выходе. Статические детали объединяются по материалу. Четырнадцать ёмкостей используют два прототипа и GPU-instancing; окна, балки и светильники переиспользуют восемь инстансных сегментов. Хмель рисуется одним InstancedMesh с ограничением 90 экземпляров, препятствия используют три кэшированные модели. Instance buffers также освобождаются при выходе и неудачной инициализации. Количество созданной геометрии не растёт с длительностью рейса. Декоративные карты не требуют сети и дополнительных PWA-ассетов.

Мобильная камера расположена сверху-сзади, смотрит вдоль дорожек и немного сопровождает плавную смену полосы. Для запуска и результата есть отдельное кадрирование с видимым лицом; переход в игровой ракурс сглажен по времени симуляции, при reduced motion он мгновенный. Существующий requestAnimationFrame-цикл вызывает независимую от частоты кадров экспоненциальную LERP в движке; React Three Fiber/useFrame не подключался. Пол и кирпичные стены прокручивают согласованные карты цвета/высоты навстречу камере, инстансные ряды циклически меняют положение. Новые дальние ряды входят за пределами тумана; размер пула покрывает весь видимый коридор. У препятствий скруглённые корпуса/цилиндрические стойки, у бочек выпуклый профиль. AmbientLight, HemisphereLight и тёплый DirectionalLight с PCF-тенями 1024×1024 дают насыщенный игровой свет внутри спокойной оболочки портала. Высокий FPS на физических телефонах не заявляется без замера.

Персонаж использует отдельные суставы плеч/локтей, бёдер/коленей/стоп. `runner-character-motion.ts` рассчитывает двухзвенную IK ног, опору с ровной подошвой, перенос ноги и противоположное движение рук. Ритм связан с пройденным расстоянием; поворот и покачивание корпуса не наклоняют стопы относительно пола. Пена и галстук имеют небольшое вторичное движение, подавляемое reduced motion. При повторе поза подката сбрасывается; пауза сохраняет позу. Силуэт кружки остаётся жёстким. Добавлены форма перчаток с пальцами, подошвы/шнурки, воротник, скруглённый профиль стекла и более выразительное лицо. Физика прыжка, столкновения и управление не менялись.

При отсутствии или потере WebGL-контекста сцена переключается на встроенный Canvas 2D с той же игровой логикой; активный рейс при потере контекста сначала ставится на паузу. При prefers-reduced-motion убраны второстепенные покачивания, вращение коллекционных объектов и декоративная анимация. Движение мира во время запущенной пользователем игры сохраняется.

Рекорд хранится только на устройстве в `bfstaff-factory-run-best-v1`. Он не привязан к профилю и не отправляется на сервер. Общего рейтинга, новых таблиц, Supabase RPC, новых разрешений и изменения бизнес-функций нет. Серверные проблемы из отдельного аудита эта функция не исправляет.

Three.js MIT notice: `licenses/three/LICENSE`, публичная копия `/assets/licenses/three.txt`. Существующие Streamline Plump Line Free и их атрибуция сохранены; другого стиля иконок интерфейса не добавлено.

## Проверка

`npm test` включает 9 сценариев движка: детерминированность, безопасное начало, границы дорожек, прыжок/подкат, попадания, защита от повторного урона, завершение, счёт, ограничение количества объектов и сброс рейса. Дополнительно 5 проверок кинематики: обратный расчёт координат стопы из суставов, полный цикл шага без недостижимых целей, пауза/reduced motion, позы прыжка/подката без изменения игрового состояния и сброс сглаживания при повторе. Проверка переиспользования окружения контролирует покрытие туманом и непрерывность расстояний между рядами при зацикливании.

После production build:

```sh
npm run preview -- --host 0.0.0.0 --port 4418
PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1 node tests/factory-run-browser.mjs
```

Браузерный тест использует скомпилированное приложение и явные auth/data fixtures; весь внешний HTTP/WS заблокирован. Touch проверяется событиями Chromium CDP. Проверки покрывают вход в Hub, сенсорное управление, паузу навигации, WebGL context loss, работу без WebGL, reduced motion в обоих рендерах, результат/повтор/рекорд, 320/375/390/430/768/1440px и Linux WebKit. Отдельный сценарий сохраняет реальный кадр подката и проверяет возврат Hub → игра после освобождения предыдущей сцены. Ещё один сценарий перехватывает фактические drawElementsInstanced/drawArraysInstanced в WebGL и подтверждает использование instancing. Это не вход настоящего сотрудника, не проверка production RLS и не физический iPhone.

Общий регрессионный браузерный набор портала сохранён. Его ожидаемое количество пунктов «Разделы» изменено с 8 на 9 с отдельной проверкой href Hub.

Unslop/Hallmark проверены на реальных браузерных снимках. Для render-checker `qa/r407/tests/hub-design-capture.mjs` сохраняет точный DOM со статичным снимком реально отрисованного Canvas вместо активной сцены. Проверки на этих HTML оценивают вид/контраст/размеры, а интерактивность проверяется отдельно browser suite. Ответ F4 объясняет взаимоисключающие кнопки «Пауза» и «Продолжить/Поехали».

`BF_HUB_CAPTURE_MOTION=1 node qa/r407/tests/hub-character-capture.mjs` сохраняет четыре позы и короткий MP4 реального WebGL-рендера. После загрузки таймер браузера заморожен, кадры вычисляются с явным шагом времени; проверяется отсутствие дрейфа. 48 кадров кодируются в 16fps для демонстрации, это не замер FPS телефона. Для MP4 нужен ffmpeg только в QA-окружении; в приложение он не подключён.

Ограничения: физические iOS/Android и FPS на устройствах команды не измерялись; полная невизуальная доступность динамической игры не заявляется. 3D-chunk загружается отдельно от главной страницы; production build сохраняет обычное предупреждение Vite о chunk >500kB, сам 3D chunk около 591kB (152kB gzip). Время первого рендера и GPU-нагрузка зависят от устройства. Требуется фактическая проверка на самых слабых телефонах команды перед признанием игры окончательной.
