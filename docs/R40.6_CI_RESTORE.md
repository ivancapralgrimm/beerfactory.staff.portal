## Files
- `.github/workflows/ci.yml`: automatic GitHub Actions checks on `main` and `r40.*` pushes/PRs, plus manual launch
- `.github/workflows/supabase-backup.yml`: **manual-only** encrypted PostgreSQL 17 backup workflow (restored because an existing regression test requires this workflow); runs only from `main`
- `docs/R40.6_CI_RESTORE.md`: these notes

## CI stages
1. `npm ci --no-audit --no-fund` (uses package-lock.json)
2. `npm run typecheck`
3. `npm test` (existing `test:ci` suite including r40.6 and photo modal checks)
4. `npm run build`

Does not require or use Supabase credentials. No application, auth, or DB schema code is changed.

## Backup: not automatic
The backup workflow is intentionally `workflow_dispatch` only. No cron/schedule.
Before the first **manual** launch configure GitHub Actions repository secrets:
- `SUPABASE_DB_URL` (Supabase Postgres connection string, never store in repo)
- `BACKUP_ENCRYPTION_PASSWORD` (long, securely backed-up secret; losing it makes artifacts unrecoverable)

The backup uses the project's PostgreSQL 17-compatible pg_dump, encrypts with
AES-256-CBC + PBKDF2, deletes the plaintext dump and stores encrypted artifacts
for 7 days. Successful backup and restore **must be tested** before treating this
as a working recovery system.

## Installation
Upload/extract files preserving the full `.github/workflows/` path into
the `r40.6-attestation-editor` branch, not `main`.

After commit, check the Actions tab for `BFStaff CI`. Green status is needed.
Do not merge into main until the real GitHub run passes.
