# BeerFactory Staff Portal · r40.4 migration

## Goal

Move the frontend from the current static vanilla JS architecture to:

- React 19
- TypeScript
- Vite
- Tailwind CSS v4
- shadcn-compatible source components
- Motion
- Lucide
- vite-plugin-pwa

Existing backend contracts stay unchanged:

- Supabase Auth / Edge Functions / operational tables
- Cloudflare Worker
- NocoDB recipe source

## Migration rule

`main` remains stable r40.3 production until r40.4 passes its own QA.

Do not perform a big-bang port. Move one module at a time.

## Phase 1 in this package

- Vite/React/TS foundation

- Supabase session hydration

## Lessons carried forward from r40.3

- Diagnose route/session lifecycle before changing backend.
- Never treat a slow UI as proof of a slow auth backend.
- No `controllerchange -> location.reload()`.
- No global fetch interception layer.
- Do not cache Supabase API responses.
- Production navigation should prefer fresh HTML and use cache as fallback.
- First installed-PWA login is a mandatory test case.
- iOS and Android must both be tested.
- QA-only code gets removed after the experiment.
- One architectural change per diagnostic step.

## Auth invariant

Authenticated state and route state are separate concerns.

- Anonymous users are declaratively redirected to `#/login`.
- Successful login persists the Supabase session before navigation.
- Accounts that still need a recovery code are held on `#/setup-recovery`.
- A Supabase auth event cannot silently bypass recovery setup.
- No same-hash transition is relied upon to render the authenticated app.
