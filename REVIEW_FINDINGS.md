# Независимый QA-контур BFStaff v4.6

**PASS** с оговоркой об отсутствии полного авторизованного браузерного E2E.

Проверенные риски:

1. Удаление билета не должно удалять банк вопросов: SQL guard запрещает операцию, если `attestation_questions.category_id` содержит хотя бы одну запись, любого статуса. `ON DELETE RESTRICT` дополнительно защищает данные.
2. История экзаменов должна оставаться: в `quiz_attempts` нет FK на таблицу билетов, и SQL не удаляет/не меняет результаты; `preservedResults` возвращает число сохранённых результатов.
3. Последний активный билет не удаляется.
4. Администратор/owner обязателен, сервер проверяет `private.attestation_is_admin()` и ограничивает EXECUTE для `authenticated`.
5. Гонка редактирования/удаления предотвращается timestamp `updated_at` и блокировкой `attestation_settings`.
6. Удаление не может запустить ранее наблюдавшуюся ошибку `DELETE requires a WHERE clause`: в SQL есть ограничение `WHERE id=p_category_id`.
7. Серверные тесты, включая реальное удаление существующего самостоятельного билета, выполнялись только в транзакционном тесте с откатом. База после теста неизменна.
8. Пользователь должен отдельно выполнить миграцию и вручную установить файлы в GitHub, клиент не может выполнить миграцию автоматически.

Принципиальное ограничение: «Удалить билет навсегда» удаляет билет как определение экзамена и его план разделов, **но не историю прохождения**. Для билетов, являющихся владельцами вопросов, кнопка показывает инструкцию о переносе вопросов. Это сознательная защита от потери 335 вопросов банка.
