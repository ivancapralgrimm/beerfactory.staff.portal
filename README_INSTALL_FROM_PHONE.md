# BFStaff r40.6 · v4.6 · Управление билетами

## Назначение

В разделе **Управление персоналом → Аттестации → Настройки**:

- В «Дополнительно» кнопка **«Скрыть категорию»** переименована в **«Отключить билет»**.
- Для любого билета (активного или черновика) доступна новая кнопка **«Удалить билет навсегда»**.
- Удаление требует точного ввода названия билета. Это не переименование и не отключение, а полное удаление *определения билета и его набора разделов*.
- История прохождения сотрудников и архив версий вопросов не удаляются.
- Если билет является владельцем вопросов банка (включая архивные и мягко удалённые), удаление блокируется. Сначала перепривяжите вопросы в редакторе к другим билетам. Самостоятельные билеты без прикреплённых вопросов удаляются независимо от их активности, кроме последнего активного билета.
- Личные настройки экзаменов, пороги, банк вопросов и работа аттестации не изменяются.

После ручной установки файлов можно попросить ChatGPT отдельно применить *только* v4.6 SQL через подключённый Supabase. Производственная база в процессе подготовки пакета не изменена.

## Проверка после установки

1. Дождаться `READY` в Vercel на коммите v4.6.
2. Открыть `#/admin` → Аттестации → Настройки. В любом **активном** билете открыть «Дополнительно» и убедиться, что написано «Отключить билет».
3. У самостоятельного билета без связанных вопросов открыть «Дополнительно» → «Удалить билет навсегда». Сначала открыть форму и проверить, что подтверждение заблокировано без ввода точного названия; нажать «Отмена» и убедиться, что ничего не пропало.
4. Для основной категории «Бар» проверить сообщение о защите привязанных вопросов. **Не пытаться удалять базовые билеты**, пока в них находятся вопросы.
5. Для реального удаления выбрать только **заведомо ненужный** самостоятельный билет, точно ввести название, подтвердить, обновить страницу. Билет должен исчезнуть из списка. Исторические результаты, если были, должны остаться в «Результатах».
6. Под обычным сотрудником не должно быть доступа к этим операциям.
7. Убедиться, что новый билет можно создать и включить, а старые билеты проходятся как раньше.

## Проверки и ограничения

- Проверено на реальной схеме Supabase с принудительным **откатом транзакции**: права, защита банка, конфликт версии, удаление билета, сохранность результатов, целостность остальных активных билетов. `PASS`. Новая RPC в рабочей базе **пока не установлена**.
- 17/17 локальных Node тестов, включая сохранённые тесты из v4.4.
- TSX и TypeScript транспилируются без синтаксических ошибок.
- **Полный Vite/TypeScript build на всём репозитории и E2E под авторизованным пользователем не проводились.** Vercel будет первой проверкой полного билда после ручной установки.
- Список вопросов и данные в Supabase не удалялись и не редактировались.

## Изменения ограничены

- 1 изменённая React-страница
- 1 новый клиентский API-модуль
- 1 новая SQL-функция/RPC и права вызова
- 1 ранее уже применённая SQL-миграция для истории репозитория
- локальные тесты

В SQL используется `DELETE ... WHERE id = p_category_id`; массовых `DELETE` нет. Без прав администратора/owner сервер отклоняет удаление.
