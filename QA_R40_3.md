## Known offline limitation

Real-device iPhone/Safari testing confirmed partial offline operation, not a fully offline-first portal.

Supported offline behavior:
- app shell can load from the service worker cache;
- previously cached recipes remain usable;
- the UI reports offline state.

Not guaranteed offline:
- Dashboard data;
- Knowledge/Attestation navigation for prolonged offline sessions;
- Shift;
- Handover;
- other Supabase-backed state.

Shift and Handover intentionally remain server-authoritative. r40.3 does not implement an offline write queue, background synchronization or conflict resolution.

This limitation is accepted for r40.3 and is not a release blocker. Full offline-first behavior, if required later, should be implemented as a separate feature rather than expanded inside this hardening release.
