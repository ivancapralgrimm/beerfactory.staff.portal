# NocoDB one-time setup · Заведение

Перед включением Worker editor v5 добавить поле `Заведение` в обе таблицы BAR и KITCHEN.

Рекомендуемая конфигурация:
- Field name: `Заведение`
- Type: `Single Select`
- Choices: `BF`, `BB`, `BF/BB`
- Default value: `BF`

`BF/BB` — каноническое значение для общей позиции. Если в старой строке уже записано `BB/BF`, frontend и Worker тоже читают её как общую позицию, но редактор при следующем сохранении пишет каноническое `BF/BB`.

NocoDB default применяется к новым строкам и не обязан автоматически заполнить старые строки. Это нормально: frontend и Worker считают пустое старое значение `BF`.

Также в поле `Статус` оставить только варианты:
- `Актуальный`
- `Архив`

Если в базе реально существуют строки со старым значением `Черновик`, не публиковать их автоматически: Worker v5 временно трактует их как `Архив`. Массовую правку реальных записей выполнять отдельно после проверки списка.

После создания поля проверить на одной тестовой/безопасной записи:
1. чтение `/menu` возвращает `venue: "BF"`, `"BB"` или `"BF/BB"`;
2. KITCHEN с `BF/BB` показывается и в `Кухня BF`, и в `Кухня BB`;
3. admin create/PATCH сохраняет `Заведение` и для общей позиции пишет `BF/BB`;
4. BAR/KITCHEN source-aware IDs не меняются.
